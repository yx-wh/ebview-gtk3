# 词典组首选项 —— 手动测试用例

覆盖本次改动：多选（Ctrl/Shift）、整块上移/下移、多行拖拽、Delete/Insert/Ctrl+方向键。
对象：`src/pref_dictgroup.c` 的「Dictionary Group」页。

## 0. 环境准备

```sh
./build.sh                       # 或用已构建的 build/ebview
mkdir -p /tmp/ebtest             # 必须先建好，$HOME 不存在会直接退出
# 复制一份真实词典组配置，省得从空列表手工建档
mkdir -p /tmp/ebtest/.ebview
cp ~/.ebview/dictgroup.xml /tmp/ebtest/.ebview/
HOME=/tmp/ebtest ./build/ebview   # 用独立 HOME，避免污染真实配置
```

> 测试实例的增删改只写 `/tmp/ebtest/.ebview/dictgroup.xml`，不会动 `~/.ebview`（`preference.c` 用 `getenv("HOME")` 拼 `user_dir`）。想自证隔离性，开测前记一下指纹，测完比对：
>
> ```sh
> md5sum ~/.ebview/dictgroup.xml      # 前后应一致
> ```
>
> 下文的 `$HOME/.ebview/dictgroup.xml` 在测试环境里就是 `/tmp/ebtest/.ebview/dictgroup.xml`；**不要**写成 `~/`（`~` 永远是你的真实家目录）。

> 若出现 `CRITICAL : Failed to create directory : /tmp/ebtest/.ebview`，是 `$HOME` 目录本身不存在：程序只 `mkdir` 一层 `.ebview`，父目录缺失时 `ENOENT` 直接 `exit(1)`。补 `mkdir -p` 即可。

- 配置目录：`$HOME/.ebview`，词典组顺序存在 `$HOME/.ebview/dictgroup.xml`（可直接 `cat` 看顺序，比肉眼比对快）。
- 数据要求：**至少 2 个组，每组至少 3 本词典**（可用「Search Disk」批量加）。只支持两级：组 → 词典，不要造三级嵌套（`save_dictgroup()` 只遍历两层）。
- 打开路径：菜单 → 首选项 → 「Dictionary Group」页。
- 每步做完点 **Ok** 再 `cat dictgroup.xml` 校验顺序。想放弃改动点 **Cancel**（或直接关窗、按 `Esc`）：不写盘，并把这页的列表回滚到打开时的样子。

记录方式：`结果` 列填 `PASS` / `FAIL` / `SKIP`，FAIL 请附「实际顺序」和是否崩溃/终端报错。

## 已知风险 / 重点观察项

- **R1（DG-18，已修）**：混选不同组的行时，原先整块只有一个边界判断，一本词典到顶就会冻住整个选区。现在先按父级拆成多个块各自移动，再最后处理组行（组行交换会改写子行路径）。仍需留意：组行与它自己的子行同时被选中时，子行先动、组行后动，结果应等于"子行在组内挪一格 + 整组挪一格"。
- **R2（DG-32）**：`up_item()` / `down_item()` / `remove_item()` 入口都会 `edited = FALSE`，即右侧尚未提交的属性编辑会丢失。
- **R3（DG-15）**：边界保护只看块首行；若块内行跨了组边界（部分在组内、部分在父级），仍可能只移动一部分。
- **R4（DG-36，已修）**：换组走的是「复制行 → 删除原行」。原先边复制边删除，删掉一行后同组后续行的**路径下标全部前移**，于是 3 本只搬过去 2 本、甚至搬错行。现在先把所有源行解析成 `GtkTreeIter`，统一复制、再统一删除（iter 在其它行删除时仍有效）。
- **R5**：`save_dictgroup()` 只遍历两层，词典必须停在组下一层；任何让词典变成组、或让组变成三级的操作都应被拒绝。
- **R9（Cancel 的范围）**：`Cancel` 只保证"不写配置文件"，并对**本页**做了完整回滚（打开时对 `dict_store` 拍快照，取消时清空重建，`BOOK_INFO` 直接复用不重新 bind）。其它页（Web 检索、Directory Group、Filter、Shortcut 等）目前只做到不写盘，内存里的列表仍会带着改动，重新打开首选项时会看到。要一并回滚可以照同一套快照机制补。
- **R8（DG-25/DG-45/DG-46，已修）**：组行原先只能落在另一组的**那一行标题**上（子词典行一律被判非法），而标题只有一行高、中间还隔着整组子项，实际几乎不可能命中。现在拖动组行时，**该组的整个子项区域都算它的落点**，落在上半 → 插到该组之前，落在下半 → 插到该组之后。
- **R7（DG-21/DG-22，已修）**：从多选中的某一行开始拖，GtkTreeView 会把选区塌缩成被按住的那一行，于是只带走一本。现在在 `button-press-event`（早于 GtkTreeView 默认处理）记下当时的选区，`drag-begin` 里若发现选区被塌缩就恢复，拖拽载荷因此包含全部选中行。副作用：单击（不拖）仍是正常塌缩，行为不变。
- **R6（DG-16，已修）**：多选 Remove 段错误。每次 `gtk_tree_store_remove()` 都会发 `changed`，属性面板随即把输入框内容写回 `last_iter`，而该行可能正是刚被释放的节点。现用 `removing_rows` 屏蔽批量删除期间的 `changed`，并在 `update_last_dictionary()` 里加 `gtk_tree_store_iter_is_valid()` 校验。
